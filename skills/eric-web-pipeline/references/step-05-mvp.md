# Step 5 · MVP 核心实现 — Core Build (Frontend & Backend)

> 中文速览：实现 spec 里的核心功能，做出**最小端到端可用切片**——用户能走完主流程，哪怕视觉还是素的。原则（AGENTS.md 第 2 条）：先切片再分层长大，每层都可验证。打磨留给 Step 7，本步只求"功能对、流程通"。

## When you're in this step · 判定信号

- 骨架能跑、tokens 就位，开始往里面填真实功能；
- progress 文件 Step 4 已勾选。

## Inputs · 进入条件

- `spec.md` 的任务分解表；
- 可运行的骨架（Step 4 产物）。

## Action checklist · 行动清单（通用）

1. **按任务分解顺序实现**，一次一个任务，每个任务完成后跑最小验证；
2. **主流程优先**：先打通"用户进来到完成核心动作"的整条链路，再做次要页面；
3. **三态补齐**：每个数据驱动的界面实现 loading / empty / error 态（spec 里已定义）；
4. **真实数据结构**：用接近真实的 mock 数据（长度、极端值），别用 "Lorem ipsum" 和 "Test"；
5. **语义与可访问性基础**：语义化 HTML、表单 label、按钮可键盘到达——现在做几乎零成本，Step 8 补课很贵；
6. 每完成一个任务，在 progress 文件记录状态。

### Path A 增量（营销/作品集站）

- [ ] 按 spec 的 section 顺序实现全部区块，文案用真实或接近真实的草稿；
- [ ] 响应式随写随查：每写完一个 section 看一眼 375px 宽度；
- [ ] 表单（如有）先接 mailto/表单服务占位，标记 TODO。

### Path B 增量（Web App 后端子流程）

按此顺序推进，每层都可独立验证：

- [ ] **数据层**：按 spec 数据模型建表/迁移；写 seed 脚本灌入测试数据；
- [ ] **API 层**：实现 spec 的端点清单；统一错误格式；每个端点至少手测正常+一种失败路径；
- [ ] **认证**：接入选定方案（Clerk/Auth.js/Supabase Auth）；保护路由与服务端鉴权双重校验；会话过期行为符合 spec；
- [ ] **授权**：服务端每个 handler 校验资源所有权（"能登录"≠"能看这条数据"）；
- [ ] **支付（如需要）**：Stripe/国内支付走官方示例起步；**必须**用 webhook 而非前端回调确认支付结果；测试模式全流程跑通（成功/失败/退款）；金额一律服务端计算；
- [ ] **前端接线**：数据获取、变更（mutation）、乐观更新策略、表单提交与校验回显。

### Path C 增量（3D/创意体验）

- [ ] 场景骨架先行：相机、灯光、主物体就位，交互占位；
- [ ] 性能预算落地为代码：draw call 合并、纹理尺寸上限、DPR 上限（`Math.min(devicePixelRatio, 2)`）；
- [ ] 降级路径：WebGL 不可用时给静态图/简化版；
- [ ] 加载策略：模型/纹理压缩（Draco/KTX2）、加载进度指示。

## Decision tables · 决策表

| 情境 | 选择 |
| --- | --- |
| 任务比预想大 | 再切小，先把半个任务做成可验证切片 |
| spec 与实现冲突 | 改 spec（记录变更），不悄悄偏离 |
| 某功能可做可不做 | 对照 brief：不在验收标准里的，记入 backlog 不做 |
| 阻塞在外部依赖（文案/API key） | 用占位继续推进主线，progress 文件记为 blocked 项 |

## Exit criteria · 出口质量门

- [ ] spec 任务分解表中的核心任务全部完成；
- [ ] 主流程端到端可走通（本地环境），三态都有样子；
- [ ] （Path B）认证/鉴权/支付按上方子清单逐项过；
- [ ] （Path C）主场景在主视口稳定 60fps 或有记录的降级；
- [ ] 控制台无 error；已实现的页面在桌面与移动宽度无破版。

## Common pitfalls · 常见坑

- **边写边美化**：功能没通就调动画——视觉打磨统一在 Step 7，本步混入会让 bug 难定位；
- **假数据陷阱**：全部用硬编码假数据，"MVP 完成"后才发现真数据结构不匹配；
- **前端鉴权错觉**：只靠隐藏按钮做权限——授权必须在服务端；
- **支付前端确认**：以后端 webhook 为准，前端回调仅做 UI 反馈；
- **一次性写太多**：写完十个文件才第一次运行——每个任务都要有小验证。
