# Step 1 · 需求锁定 — Brief & Task Contract

> 中文速览：把"想做个网站"变成一页纸的任务契约——交付物是什么、给谁看、长什么样算做完、什么不许动。这一步不写任何代码，产出物是 `brief.md`。跳过这一步直接开写，是 AI 项目返工的第一大原因。

## When you're in this step · 判定信号

- 新项目文件夹是空的，或只有一个想法/一句话需求；
- `web-dev-progress.md` 不存在（用 `templates/progress-tracker.md` 在此步创建）；
- 用户给了参考图、竞品链接、模糊描述（"做个高级的落地页"），但没有明确验收标准。

## Inputs · 进入条件

- 用户的一句话需求或想法（足矣，其余由本步补齐）；
- 任何已有约束：品牌资料、现有仓库、截止日期、预算/额度约束。

## Action checklist · 行动清单

1. **定交付物类型**（三选一，决定后续路径）：
   - [ ] Path A：营销页 / 作品集 / 编辑类页面（无后端或仅表单收集）；
   - [ ] Path B：Web App（有用户体系、数据持久化、可能的支付）；
   - [ ] Path C：3D / 创意体验（WebGL 重交互、游戏化、scrollytelling）。
2. **定受众与场景**：谁访问、在什么设备上、带着什么目的、期望他们做什么动作（CTA）。
3. **写验收标准（definition of done）**：把"高级""专业""快"翻译成可观测条件，例如：
   - "首屏 LCP < 2.5s（4G 节流）"而不是"加载快"；
   - "移动端 375px 无横向滚动"而不是"适配手机"；
   - "视觉达到参考站 X 的排版密度"而不是"好看"。
4. **划边界**：明确不做什么（本期不做博客、不接支付、支持中英文但先出英文）。
5. **收集已有资产**：logo、文案、图片、品牌色、域名、现有代码仓库。
6. **识别高风险假设**：列出让项目可能推倒重来的 1–3 个未知项（如"客户是否已有品牌字体授权"），能现在验证的立刻验证。
7. 用 `templates/brief-template.md` 写出 `brief.md`，并创建 `web-dev-progress.md`。

## Decision tables · 决策表

| 情境 | 选择 |
| --- | --- |
| 用户只给一句话，没给参考 | 正常推进，Step 2 里生成 2–3 个视觉方向供选 |
| 需求含糊到影响交付物类型或预算 | 问用户（仅此情况值得打断） |
| 需求含糊但可自行假设 | 在 brief 里写明假设，继续推进 |
| 是对现有项目的小改动 | 不走全流程，直接跳对应步骤（见 SKILL.md 快速通道） |

## Exit criteria · 出口质量门

- [ ] `brief.md` 存在，包含：交付物类型、受众、3 条以上可观测验收标准、明确的"不做"清单；
- [ ] 路径变体（A/B/C）已选定；
- [ ] 高风险假设已列出，能验证的已验证；
- [ ] `web-dev-progress.md` 已创建，Step 1 标记完成。

## Common pitfalls · 常见坑

- **把模糊词当验收标准**："大气""丝滑"无法验证——必须翻译成可观测条件；
- **过度澄清**：问一堆用户答不上来的问题；能合理假设的就假设并记录；
- **跳过边界清单**：没有"不做"清单，scope 会在 Step 5–7 无限膨胀。

## Route to existing skills · 路由

- `iterate-until-verified` 第 1 节（lock the original task）的契约提取方法；
- 复杂需求先查 Holograph 记忆（`probe <项目名>`）再决定问不问。

## Output artifacts · 产出物

- `brief.md`（任务契约）；
- `web-dev-progress.md`（步骤追踪文件，Step 1 勾选）。

## Handoff · 衔接

- 全部出口标准满足 → 进入 **Step 2 Research**；
- 后续任何一步发现需求理解错了 → 回到本步修订 `brief.md`，并在 progress 文件记录变更原因。
