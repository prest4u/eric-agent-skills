# Eric-designed-pdf

## Overview

Produce original, textbook-grade PDF teaching systems with deterministic text layout, full-page visual QA, and student/teacher leak gates. This Skill is the higher-level book system; treat `$eric-pdf` as an explicit-only Typst A4 adapter/QA route, never an automatic handoff.

## Route First

1. **Classify the artifact.** Name the output type, audience, source materials, answer visibility, profile, output paths, and overwrite policy before editing.
2. **Choose the route.**
   - If multiple PDF Skills match, choose the primary route from this Skill's boundaries and the available Skills' metadata; do not read another Skill through an absolute installed path.
   - Use the HTML book engine for student books, workbook-style samples, long course books, handbook/back-matter pages, or custom trim PDFs.
   - For lesson-pack / single-lesson course delivery, default to A4-only student/teacher outputs unless Eric explicitly asks for book-trim too.
   - If Eric asks for a full `book`, `教材全书`, or book-like course without naming the profile, stop and ask whether the delivery should be `A4`, `book-trim`, or both before scaffolding.
   - Use `lesson-a4` when the same book language must become an A4 print pack.
   - Use the Typst adapter plus explicit `$eric-pdf` QA only when Eric separately requests that adapter/QA step for a deterministic single-lesson A4 packet or student/teacher split.
3. **Read the needed references.**
   - `references/visual-dna.md`: design tokens, page rhythm, asset boundaries.
   - `references/visual-canon.md`: golden-sample page roles and design-transfer contract.
   - `references/page-role-matrix-v2.md`: full-coverage v2 template matrix for 100+ page student-book/workbook/handbook/answer-key systems; use `page_family_mode: v2-full` when claiming matrix coverage.
   - `references/student-book-form-dna.md`: professional Level 1/student-book page-form grammar, especially article/skill/practice/back-matter forms for Chinese exam grammar courses.
   - `references/reference-book-style-dna.md`: abstract Cambridge/In Use/National Geographic/GIC-style reference-book grammar; read when Eric cites those books, asks for self-study reference-book feel, or wants a student book that teaches knowledge rather than a worksheet packet.
   - `references/gaokao-course-adapter.md`: structured 22-lesson / 中高考 full-course adapter rules for `lesson_plan.json`, question/passage/writing banks, student/teacher profile separation, and long exam-course pagination.
   - `references/failure-taxonomy.md`: hard reject labels for dashboard/UI/font drift.
   - `references/review-rubric.md`: visual scoring and required review fields.
   - `references/component-grammar.md`: required textbook components and page contracts.
   - `references/production-workflow.md`: source interfaces, scaffolding, and output profiles.
   - `references/qa-gates.md`: hard gates, commands, and evidence ledger.
4. **Scaffold when starting new work.**

```bash
python3 ./scripts/new_project.py --out <project-dir> --title "<book title>" --profiles book-trim,lesson-a4 --include-typst
```

For independent A4 lesson packs, scaffold only the A4 student/teacher profiles:

```bash
python3 ./scripts/new_project.py --starter v2 --out <project-dir> --title "<lesson title>" --profiles student-lesson-a4,teacher-lesson-a4
```

For full-coverage v2 gallery/scaffold work:

```bash
python3 ./scripts/new_project.py --starter v2 --out <project-dir> --title "<book title>" --profiles book-trim,lesson-a4 --include-typst
```

For explicit student/teacher full-book edition separation, scaffold named profiles such as:

```bash
python3 ./scripts/new_project.py --starter v2 --out <project-dir> --title "<book title>" --profiles student-book-trim,teacher-book-trim --include-typst
```

The scaffold derives page size/output filenames from `book-trim` or `lesson-a4`, sets `answer_visibility` from the profile name, and gives clean student profiles QA requirements that exclude teacher-only answer-key pages.

5. **Default to a generic book identity.** For course books, prep plans, student books, workbooks, and reusable教材 systems, default to a no-student-name edition. Do not put a real/test student name such as Sample Learner in the title, page copy, asset ids, manifest prose, source paths, output filenames, or extracted PDF text unless Eric explicitly asks for a personalized edition. Sample Learner is a regression/test case, not the default product identity.
6. **De-starter the project.** For any custom book, replace the active page list, page files, renderer labels, Typst labels, manifest assets, and output filenames. No visible or source residue such as `Pathways to Better Writing`, `English Writing System`, or `canyon-cover` may remain unless `qa.allow_starter_residue: true` is explicitly set for a real starter-sample build.
7. **Lock the asset mode and image-use contract.** Use `qa.asset_mode: proof-placeholder` only for layout/design-transfer proofs. Use `qa.asset_mode: final-assets` before delivery; cover, unit-opener, photo-passage, and context visuals must then be ImageGen or licensed/owned originals with manifest prompt/source, status, focus, dimensions, and no-text policy. Final ImageGen visuals default to immediately understandable real-world imagery. Eric's preferred first family is landscape, nature, and realistic wildlife/animal photographs when the content allows; campus/classroom/library/study scenes and modern human learning/life scenes are second family when they fit better. If the final visual chooses the second family, record `family_rationale` or `nature_first_rationale` in the manifest explaining why a school/study/modern-life scene fits this content better than a nature or animal direction; missing rationale is `FINAL_ASSET_NATURE_FIRST_RATIONALE_MISSING` in QA. Do not use abstract paper sculptures, symbolic decision maps, token boards, floating strips, or concept-art contraptions unless Eric explicitly asks for that direction. Animal visuals should read as real nature/wildlife, not childish mascots or stickers unless requested. The no-text policy includes avoiding symbol-like shapes that read as letters, numbers, labels, or answer marks even when they are not technically readable text. One image may be used once only: the cover asset is cover-only, and unit-opener/photo-passage/context pages need their own asset ids and image files.
8. **Build from source.** Edit `book.yaml`, `pages/*.md`, `assets/manifest.json`, and `theme/tokens.json`; keep instructional text selectable and searchable. When Eric references Cambridge, In Use, National Geographic, or GIC books, use `reference-book-style-dna.md` to transfer only abstract page grammar: explanation/practice pairing, reference density, visual-context use, and exercise progression. Never copy logos, passages, exercises, imagery, screenshots, exact spreads, or full-page layouts.
9. **Map exam-course content into student-book form.** When converting 中高考 / 高二升高三 grammar, reading, or writing courses, use `student-book-form-dna.md`, `page-role-matrix-v2.md`, and for 20+ lesson structured courses `gaokao-course-adapter.md` to select article opener, skill/method, practice, diagram, review, teacher-key, and handbook page roles before writing pages. For 20+ real lesson courses, default to lesson-by-lesson production first: make one independent A4 lesson pack with its own cover/title/opener, `student-lesson-a4`, and `teacher-lesson-a4` profiles, review it visually, then scale to the remaining lessons. Compile a full book only after lesson-level proofs pass and after confirming whether Eric wants `A4`, `book-trim`, or both. For 24+ page galleries, long student books, or any output claiming full matrix coverage, set `qa.page_family_mode: v2-full` and let `V2_PAGE_FAMILY_COVERAGE_MISSING` block incomplete family coverage. Do not leave the book as a long numbered worksheet or a reskinned old DOCX/PDF. Keep visible-text cleanup separate from title/slug cleanup: fixing `22讲` residue by globally replacing it inside `clean_title()` or output-folder naming can create broken labels such as `第本课程`; failing to strip source prefixes can leave `第N讲` on an independent lesson cover. Treat both as `visible-sanitizer-scope-leak` / `A4_ONLY_PROFILE_RESIDUE` and block release. Treat compact teacher answer-note fusion as `teacher-key-cjk-latin-fusion`: normalize CJK/Latin boundaries in teacher-visible answers and notes before rendering.
10. **Set answer visibility per profile.** For student-visible PDFs, set `answer_visibility: student` in `qa` or profile-level `qa`; use `student-with-answer-key` only when a student answer-key page is intentionally included, and `teacher` for teacher-only answer profiles. Mark teacher-only pages with frontmatter such as `audience: teacher`, and use `include_profiles` / `exclude_profiles` only for deliberate profile-specific pages. The validator infers `student` or `teacher` from explicit profile names such as `student-book-trim`, `teacher-book-trim`, `student-lesson-a4`, and `teacher-lesson-a4` so omitted config cannot silently disable leak gates, but explicit profile `qa.answer_visibility` is still required for release-grade source clarity. The v2 HTML builder filters excluded pages before rendering and renumbers visible pages; `STUDENT_ANSWER_VISIBILITY_LEAK` is still the backstop if answer-key or teacher-only pages appear in clean student profiles.
11. **Define the teacher edition honestly.** A real `teacher-lesson-a4` / `teacher-book-trim` is not just the clean student book with answer-key pages appended. Unless Eric explicitly asks for an appendix-only key, teacher profiles must include integrated teacher affordances on student-equivalent pages, such as `teacher-page-note` margin notes and `teacher-answer-strip` answer references, plus real `teacher-guide-page` surfaces for lesson flow, likely errors, board notes, and page-by-page teaching moves. Do not render `Teacher Guide` through `teacher-answer-key`; that is `TEACHER_BOOK_APPENDIX_ONLY_DRIFT` and blocks release.
12. **Polish visible teaching language.** For student/parent-facing Chinese or mixed-language teaching text, run `eric-teaching-polish` rules before delivery: remove internal words such as route, 主动作, 维修, 闭环, 后台, 路径, and replace them with concrete learner actions. For premium 中高考 student-book/workbook outputs, use a visible title layer: page-role headings, reading passage titles, reading set headings, checkpoint labels, and question/workbook prompts should prefer clean workbook English unless Eric asks for Chinese labels. Keep Chinese where it carries exam terminology or local explanation, but do not let article titles, exercise headings, or question instructions sound like Chinese production notes. English is not automatically good enough: headings such as `Today On The Page`, `Evidence Pause`, `Practice Review`, `Method Model`, `Demo Practice`, `Tool Practice`, `Lesson Route`, `Lesson Rhythm`, `Practice Rhythm`, `Micro Skills`, `Anonymous Error Hotspots`, and `Personal Check And Course Plan` still feel like generated workflow labels; map them to printed workbook language such as `Practice Plan`, `Evidence Check`, `Review Check`, `Method Focus`, `Model Practice`, `Strategy Practice`, `Error Pattern Check`, or `Next Practice Plan`. Draft-cleanup labels such as `Clean version` and `Cleaner version` are also student-facing drift; map them to `Rewrite`, `Revision`, or `Final revision`. Cloze and MCQ prompts such as `完形填空第N空`, `第N空`, `根据全文选择`, or `选择最符合` are not acceptable student-facing workbook stems; map them to English prompts such as `Blank N: Choose the word that best fits the story, feeling, and logic.` or `Choose the best answer according to the whole passage.` Teacher-only answer rationales should also say `Blank N`, not `第N空`, so all four release PDFs share the same exam-label language. Article body text must not start with source-type prefixes such as `完形填空`, `阅读理解`, `阅读表达`, or `任务型阅读`, and must not keep trailing source section markers such as `三、`; move the type into English title/notes and strip these residues before chunking passage text. Cloze article bodies also need OCR cleanup before rendering: patterns such as `17 _ side`, `whenI__18`, `my __19 onthe`, `He __ 24 _`, `30___ flights`, `ev- ery`, or `Situation ,is` must become clean prose with stable inline `.blank` spans, not literal underscores or orphan rules. Shared renderer defaults for workbook prompts must also be English, e.g. `Check this page before moving on.` and `Which question type should I practise next?`, never `进入下一页前...` or `下次先改...`; avoid backstage verbs such as `repair` in student-facing English. For long 中高考 books, keep the Chinese course identity on the cover/title page when needed, but set an English `footer_title` so frontmatter folios do not repeat `Lesson Map • 天津高考英语一轮复习` across student pages.
13. **Protect real terms and fused article phrases before cloze conversion.** In 中高考 cloze articles, numbers inside real English terms such as `Covid-19 related` are not blanks, and OCR fusions such as `to bea leader` must become `to be a leader`. The generator must protect hyphen-number terms before converting `16-35` cloze slots. It should also keep letter-em-dash-letter phrases together with no-break word joiners on both sides of the em dash so `person—something` cannot render as either `person—` at the line end or `—something` at the next line start. Broken output such as `Covid-____ related`, `Covid-<blank> related`, `to bea leader`, or visually split `person— something` is `rendered-text-glitch` / `student-prompt-language-drift`.
14. **Configure QA, do not bypass it.** If a project has custom filenames, 14+ pages, custom templates, answer-visibility rules, or final assets, add `qa` and `profiles.<profile>.outputs` settings in `book.yaml` or pass the matching `qa_textbook_pdf.py` CLI flags. Do not replace the skill validator with a weaker project-local script.
15. **Use the visual contract for rebuilds.** If Eric says the result is not good enough, or a project drifted into template/dashboard/UI territory, stop patching and restart from `visual-canon.md` plus `failure-taxonomy.md`.
16. **Run gates before reporting.** Freshly build HTML/PDF, render page screenshots, run the validator, inspect contact sheets, and record remaining risk.
17. **Keep QA evidence layers separate.** A normal `qa_textbook_pdf.py` run writes `_qa/textbook-qa-<profile>.md/json` and proves executable machine gates. A `--require-human-review` run writes `_qa/textbook-qa-<profile>-release.md/json` and proves or blocks formal visual release; this is the `release_gate` evidence layer. Do not let the release-gate failure overwrite the machine QA report, or future audits will confuse P0/P1-clean build evidence with a missing 9.5 visual PASS.

**🔴 CHECKPOINT · Fresh Evidence Lock**
Do not trust an old PDF, old screenshots, or an old review note. Rebuild HTML, export PDF, regenerate full-page PNGs/contact sheets, and rerun `qa_textbook_pdf.py` after the last content/CSS/source edit. If the source tree has changed after the current HTML/PDF, or the review file predates its contact sheet/key pages, the evidence is stale even when the paths exist. Generated page folders must also be free of Finder/iCloud-style stale duplicates such as `pages/0002-title 2.md`; even inactive duplicates pollute source scans and future reviews. For 500+ page / four-profile projects or 20+ independent lesson-pack batches in iCloud-backed or synced folders, render and validate profiles sequentially, not in parallel, then run a conflict-file cleanup/settle check before release QA; concurrent or freshly synced renders can create `... 2.png`, `book 2.yaml`, or `LESSON_ADAPTATION_REVIEW 2.md` duplicates after an otherwise clean build. The batch script must do a final whole-delivery conflict scan after all lessons, not only per-lesson checks, and a complete batch must not leave a stale `lesson-*` directory outside the manifest. Machine QA reports `SOURCE_OUTPUTS_STALE`, `RENDERED_ARTIFACTS_STALE`, `STALE_DUPLICATE_PAGE_FILES`, `RENDERED_PAGE_CONFLICT_FILES`, `QA_EVIDENCE_CONFLICT_FILES`, or failed `review_fresh_after_artifacts`.

## CHECKPOINTS

**🔴 CHECKPOINT · Scope Lock**
Stop before scaffolding or overwriting. Confirm output type, audience, profile, source files, answer visibility, output path, and overwrite policy.

**🔴 CHECKPOINT · Generic Edition Lock**
Default deliverables are generic no-student-name editions unless Eric explicitly asks for a personalized edition. Personalized editions may contain a real/student/test name only in intentional title/copy/filenames and must keep that name out of reusable templates. For generic editions, scan generator/source, page markdown, asset manifest prose, generated HTML, extracted PDF text, output filenames, and visible rendered pages for student-name residue. Sample Learner is a regression/test case used to validate the system, not the default target or identity for the skill.

Do not treat generic edition work as a string-replacement pass. A final generic book needs its own book identity: a publishable `identity.cover_title`, a clear `identity.positioning`, a named generic `identity.audience`, and an `identity.front_matter_role` explaining what p1-p3 establish beyond "how to use this material." A cover/title that only says `IELTS备考计划`, `学习计划`, `student workbook`, or `A4 lesson pack` is `generic-book-identity-weak`; machine QA reports `GENERIC_BOOK_IDENTITY_WEAK`. Rebuild p1-p3 as cover, title/navigation, and scope map before scaling the full book.

For 24+ page books with `page_family_mode: v2-full`, check book rhythm in addition to family coverage. A matrix can pass while the contact sheet still feels like a repeated form pack. Avoid long runs of planner/final-check/exam/form pages without editorial anchors such as unit openers, article/evidence pages, photo passages, handbook/reference pages, or answer-key back matter. Machine QA reports `PAGE_ROLE_RHYTHM_WEAK` as the radar signal; visual release cannot ignore it without explicit user acceptance.

**🔴 CHECKPOINT · Asset Generation Pass Lock**
Before final delivery, set `qa.asset_mode: final-assets`. Cover, unit opener, photo passage, and context/hero visuals cannot remain `procedural-raster`, proof, starter, sample, draft, placeholder, or temporary assets. ImageGen assets must be generated as bitmap context only, saved into the project, and registered in `assets/manifest.json` with `kind: imagegen`, `status: approved_final`, `prompt` or `generation_prompt`, `source_note`, `focus`, `allowed_templates`, and `text_policy` that says no visible text and no questions/answers/teaching body. Final images must be easy to understand at first glance. Preference order: first use realistic landscapes, nature scenes, and real wildlife/animal photographs when they can carry the mood; then use campus/classroom/library/study scenes or modern human learning/life scenes when those fit the material better. If using the second family, add `family_rationale` or `nature_first_rationale`; QA reports `FINAL_ASSET_NATURE_FIRST_RATIONALE_MISSING` as a P2 review issue when the manifest gives no reason. Reject abstract paper sculptures, symbolic decision maps, token boards, floating blank strips, conceptual evidence boards, and other hard-to-explain generated contraptions as `abstract-asset-drift`; machine QA reports `FINAL_ASSET_UNINTERPRETABLE_SCENE` when the manifest lacks real-world scene anchors or contains unnegated abstract/symbolic drift terms. During visual review, reject not only readable text but also fake handwriting, blurred lorem ipsum, number-like symbols, letter-like icons, checkmarks, answer marks, or label-like pictograms that could be mistaken for teaching content. Final cover/hero assets also need `content_brief`, `visual_direction`, and `uniqueness_note`: the cover image must be designed from the actual lesson/book content and should feel different across courses rather than reusing a generic template mood. One image may be used once only: `cover_hero` assets must have `allowed_templates: ["cover"]` and must not appear in unit opener, photo passage, or content pages. Unit opener and photo-passage visuals need separate image files and separate asset ids. If the task is only a layout proof, keep `qa.asset_mode: proof-placeholder` and state clearly that the asset pass is not final.

**🔴 CHECKPOINT · Visual Release Lock**
Stop before claiming ready. Do not write or accept `FINAL_VISUAL_REVIEW: PASS` unless `_qa/contact-sheet-<profile>.png`, `_qa/rendered-pages/<profile>-page-*.png`, and `_qa/visual-review-<profile>.md` all exist. The review must include `Reviewer:`, `Checked:`, `Contact sheet:`, `Key pages:`, `Canon comparison:`, `Reject patterns checked:`, `Font decision:`, `Visual diagnosis:`, `Weak pages:`, `Score: 9.5/10` or higher, `P0: 0`, and `P1: 0`. If the proof is below 9.5, do not leave a stale pass or vague pending note; write `FINAL_VISUAL_REVIEW: FAIL` or `FINAL_VISUAL_REVIEW: PENDING`, name the weak pages and reject labels, and rerun QA so the failure is visible.

**🔴 CHECKPOINT · Review Residue Lock**
When Eric asks to search/review/fix all issues, treat every named `P2`, `Weak pages:`, `Remaining risk:`, and old formal-review weak point as an active repair queue, not as acceptable release notes. Search `_qa/`, `reviews/`, and the skill validation ledger before editing; fix the named pages or explain why a risk is explicitly accepted. After repair, regenerate both profiles, rerender contact sheets, update the visual-review files, and write the root-cause rule back into this skill.

**🔴 CHECKPOINT · Topic Template Fidelity Lock**
Before visual release, inspect repeated template families such as `categorizing-chart`, `vocab-bank`, `handbook`, `article-opener`, and `final-check`. The template name and components are not enough: row labels, examples, record prompts, and mini rules must belong to the current unit/topic. A listening page using generic writing rows, a health/work bank using starter copy, or a transfer page without actual source/target topics is `topic-template-drift` and blocks "all issues fixed" claims.

**🔴 CHECKPOINT · Cover Title Lock**
If a cover title contains Chinese, a student name, or a mixed phrase such as `IELTS备考计划 for Sample Learner`, do not allow browser wrapping to split the title. Use a deliberate single-line lockup or an intentional editorial line break; a broken glyph/name wrap is `title-wrap-break` and blocks visual release.

**🔴 CHECKPOINT · Mixed Title Scale Lock**
If a cover or title page uses one H1 lockup for a mixed title such as `IELTS备考计划 for Sample Learner`, every part of that same title must keep the same optical scale and weight. Do not make `for Sample Learner` or a student-name suffix smaller with `.86em` / `.85em` styling or an absolute-small cover rule. Either keep the suffix at `font-size: 1em` with inherited weight, or move it to a real subtitle/meta line. `mixed-title-scale-drift` blocks visual release.

**🔴 CHECKPOINT · Cover Brand Lock**
Every final cover must include `Eric Teaching Studio` as a restrained bottom-right `.cover-brand` mark. Because final covers use real photos, the mark must also have a contrast treatment such as a restrained scrim, background, text shadow, or equivalent CSS so it remains readable over dark jackets, forests, wildlife, or busy campus scenes. Do not put the course stage, level, or audience such as `高二升高三` in the cover top-right corner; that metadata belongs on the title/navigation page, inside the book, or in a quiet subtitle/meta line. A missing Studio mark is `cover-brand-missing`; a low-contrast mark is `cover-brand-low-contrast`; a cover-top stage badge is `cover-stage-badge`; these block visual release and machine QA reports `COVER_BRAND_MARK_MISSING` / `COVER_BRAND_CONTRAST_WEAK` / `COVER_TOP_LEVEL_BADGE`.

**🔴 CHECKPOINT · Control Selector Isolation Lock**
Text-bearing components may contain `.blank`, title fragments, emphasis spans, captions, icons, and markers in the same label/row. Never style generic descendant spans such as `.editing-checklist label span` as UI controls. Use explicit marker classes such as `.check-mark`, then verify checklist/table/sidebar blanks remain blanks rather than checkbox-like rectangles. `control-selector-leak` blocks visual release and is a machine QA failure.

**🔴 CHECKPOINT · Student Language Lock**
Before final PDF review, scan the rendered/extracted student text. Visible pages must not say `Route`, `主动作`, `维修`, `路由`, `路径`, `后台`, `闭环`, `得分动作`, `动作卡`, `自检卡`, `score moves`, `scorecard`, `self-check card`, `surface family`, `page rhythm`, `design system`, `Clean version`, `Cleaner version`, or similar production/tool words. Use `eric-teaching-polish` for the rewrite when the copy feels like a lesson-production pipeline, cleanup stage, or coaching-app dashboard. In premium 中高考 lesson packs, do not expose Chinese production-note titles such as `路线`, `微技能训练`, `段落诊断`, or `作业说明` as raw page headings. Add a generator-level visible-title map, e.g. `In This Lesson`, `Before You Begin`, `Evidence Check`, `Method Focus`, `Model Practice`, `Writing Moves`, `Review Check`, `Opening Notes`, `Evidence Notes`, and `Before You Leave`, and keep those mappings in the source generator rather than hand-editing generated pages. Avoid English-but-AI or tool-surface headings such as `Today On The Page`, `Evidence Pause`, `Practice Review`, `Method Model`, `Demo Practice`, `Tool Practice`, `Lesson Route`, `Lesson Rhythm`, `Practice Rhythm`, `Micro Skills`, `Practice Log`, `Start Record`, `Personal Check`, and `Self Check`; they still sound like generated workflow labels instead of printed workbook language. Reading passage titles and reading set headings must be English, even when the source passage title is Chinese; use neutral source-safe titles such as `The School Science Fair` and `Guided Reading: The School Science Fair`. Inner workbook page headings should also be English-first; cover/course identity may keep necessary Chinese, but activity, paragraph-practice, reading, writing, final-check, handbook, and vocab-bank headings must not fall back to raw Chinese source titles or AI-ish page labels. `WORKBOOK_TITLE_LANGUAGE_DRIFT` blocks release. Questions, record prompts, checkpoints, and workbook labels should prefer English in student-book/workbook mode, while Chinese may remain for exam-specific explanations and local grammar terms. Student rewrite tasks should say `Rewrite`, `Revision`, or `Final revision`, not `Clean version` / `Cleaner version`; this should be enforced in source/generator validators, not cleaned by hand in generated HTML. Cloze/MCQ shells such as `完形填空第N空`, `第N空`, `根据全文选择`, and `选择最符合` must be converted by the generator, not cleaned by hand after rendering. Article body source prefixes such as `完形填空 Life is...` and trailing section markers such as `三、` must be stripped before rendering; source type belongs in English notes like `Text type: cloze`. Cloze article OCR must also be normalized before rendering: single/double underscores around question numbers, fused words like `whenI`/`onthe`, line-break hyphenation like `ev- ery`, and spacing like `Situation ,is` are `rendered-text-glitch` / `student-prompt-language-drift` until repaired. The validator reports `STUDENT_PROMPT_LANGUAGE_DRIFT` when student workbook bodies expose production-shell language such as `接下来我们`, `本页回收`, `复盘记录`, `微技能训练`, `作业说明`, `今日记录`, `完成前检查`, `进入下一页前`, `下次先改哪一类题`, Chinese source-type prefixes/section markers, raw cloze OCR markers, or these Chinese cloze/choice stems; fix the generator/title map or shared renderer defaults rather than hand-editing one generated page. Also inspect the HTML renderer label layer: do not let folios, badges, ribbons, or timing strips translate back to `本讲路线`, `课前记录`, `第10讲`, or `时间`; use `Lesson Map`, `Before You Begin`, `Lesson 10`, and `Time` in English-first workbook mode. For Chinese-identity course books, add `footer_title` in `book.yaml` and make the renderer prefer it in frontmatter folios so `Lesson Map • <Chinese course title>` does not become a repeated student-page UI label.

**🔴 CHECKPOINT · Blank Line Baseline Lock**
Before visual review, inspect fill-in-the-blank lines in rendered pages. True exercise blanks must sit visibly near the lower writing baseline/lower edge of the line box, not around the vertical center of the line. Runs such as `___` or `______` in any visible exercise text, including paragraphs, questions, instructions, word-box items, activity items, tables, planner prompts, and checklist lines, must render as `.blank` elements, not literal underscore glyphs. The starter CSS enforces this with a zero-height bottom-rule model: `.blank { height: 0; vertical-align: -0.82em; }` and `.question-lines .blank { vertical-align: -0.88em; }`. Model-note / paragraph-practice cloze blanks are a separate optical case: keep them as `.blank`, but add `.paragraph-practice p .blank { vertical-align: -0.22em; }` so short blanks sit with the serif paragraph text instead of dropping into the next line gap. Workbook-record prompt blanks are a third optical case: use `.record-prompt .blank { vertical-align: -0.32em; }` so a prompt such as `next time I will practise ____.` or `下一次我只练 ____。` reads as an inline cloze, not a dropped answer line. Ordinary inline cloze blanks inside activity instructions/items, word boxes, words-to-know, table cells, planner prompts, review rules, editing checklist labels, handbook rows, and answer tables are a fourth optical case: use the inline cloze group at `.activity-block p .blank`, `.activity-block li .blank`, `.word-box .blank`, `.words-to-know .blank`, `.textbook-table td .blank`, `.review-rules .blank`, `.planner-prompt .blank`, `.editing-checklist label .blank`, `.handbook-page .blank`, and `.answer-table .blank` with `vertical-align: -0.30em`. The older global `-0.64em/-0.68em` alignment still reads too centered and is blocked by QA. `floating-blank-line` is a visual blocker for workbook/activity pages, and `LITERAL_UNDERSCORE_BLANKS` / `BLANK_BASELINE_CSS_WEAK` are machine gate failures.
If a blank is followed by punctuation, such as `____.`, `____,`, `____。`, or `____，`, wrap the blank-plus-punctuation as one no-wrap `.cloze-keep` unit and keep the punctuation attached with a nonbreaking joiner so the period/comma/Chinese punctuation cannot orphan onto its own line.
Narrow phrase contexts are a fifth optical case. Word boxes, mini-rule cards, captions, sidebars, compact lookup rows, and narrow table/checklist cells must not let a blank become a lonely horizontal rule on its own line. Word-box choices should render as no-wrap phrase items (`.word-box-item`) with compact blanks (`.word-box .blank { vertical-align: -0.26em; }`) and should wrap whole choices to the next row rather than splitting around the blank. Handbook mini rules should normally avoid open answer blanks; if a cloze is truly needed, render it as a compact no-wrap unit with `.cloze-keep` and `.handbook-rules .blank { vertical-align: -0.24em; }`. Treat a standalone blank line in these narrow contexts as `orphan-slot-line`, a subtype of `floating-blank-line`.
Question prompts that already receive dedicated writing lines are a sixth optical case. In `.question-lines li`, author placeholders such as `____` / `______` are content authoring hints, not visible inline cloze blanks. Strip those placeholder runs with `prompt_text_before_write_lines()` and let the `.write-line` below carry the answer space. Never render both `.blank` and `.write-line` inside the same question item; this is `question-line-double-blank` and the machine gate `QUESTION_INLINE_BLANK_WITH_WRITE_LINE` must fail it.
Label-prefixed planner prompts are a seventh optical case. A prompt such as `Connector: ____ Evidence: ...` can render the blank too weakly because the short slot is squeezed between a label and long prose while the same row already has full writing lines. When a planner/check row has dedicated `.write-line` space, prefer visible prompt text such as `Connector first. Then use this evidence: ...` and let the answer line carry the written response. Treat weak or visually missing label-prefixed planner blanks as `planner-label-blank-weak`.

**🔴 CHECKPOINT · Exam Stem Slot Lock**
MCQ and cloze stems are not writing blanks, model-note blanks, word-box blanks, or answer-line blanks. Inside `exam-mini-set` / `.guided-mcq-set`, author placeholders such as `____` must render through a dedicated `exam_stem_text()` / `.exam-stem-slot` system. Bind following punctuation with `.exam-stem-keep` so `____.`, `____,`, `____。`, and `____，` cannot drift, orphan, or sit at the wrong height. A `.guided-mcq-set p .blank`, a literal underscore run, missing `.exam-stem-keep`, or exam stem punctuation detached from the slot is `exam-stem-slot-drift`; machine QA reports `EXAM_STEM_SLOT_DRIFT`.

**🔴 CHECKPOINT · A4 Sentence Map Surface Lock**
Long sentence analysis on A4 must not use a wide three-column table. A `sentence-map` page in `student-lesson-a4` / `teacher-lesson-a4` should render as a stacked paper surface such as `.sentence-map-card-stack` with `data-surface-family="sentence-map"` and a real `data-surface` value, using separate sentence / analysis / check fields that can wrap naturally. A4 sentence-map pages that still use `.textbook-table` or squeeze long analysis into narrow columns are `a4-sentence-map-table-cramp`; machine QA reports `A4_SENTENCE_MAP_TABLE_CRAMP`.

**🔴 CHECKPOINT · Planner And Backmatter Lock**
Before scoring a proof set, inspect the review/planner and handbook pages at full-page PNG size. A planner must feel like a tactile workbook writing surface, not a spreadsheet; a handbook must have lookup density such as compact rows, mini rules, or reference tables, not another sparse worksheet. `plain-planner-table` or `weak-backmatter` blocks a 9.5 visual release.

**🔴 CHECKPOINT · Role Variant And Unique Opener Lock**
Before scaling or releasing a 50+ page v2 book, inspect planner/final-check role rhythm and all unit openers together. Pages such as monthly route maps, daily schedules, Task 2 answer sheets, Task 1 visual plans, speaking cue cards, listening replay records, and reading evidence closes must not all render through the same generic `writing-planner` / `final-check` surface; give each role a semantic `variant` and topic-specific row language. Unit openers must not all share the same color and bottom-band structure; record per-unit `opener_accent`, `opener_band`, and `opener_layout`, and use at least two visible opener structures across a six-unit book. `PAGE_ROLE_VARIANT_RHYTHM_WEAK` and `UNIT_OPENER_VARIATION_WEAK` block visual release until repaired or explicitly accepted by Eric after seeing the updated contact sheet.

**🔴 CHECKPOINT · Optional Structure Library Lock**
Before scaling a student-book system, read `page-role-matrix-v2.md#optional-structure-library`. A template can repeat for good pedagogical reasons, but repeated families need a visible `variant:` decision and enough optional structures to respond to the lesson content. Activity, skill-method, categorizing-chart, exam-mini-set, handbook, vocab-bank, article/evidence, and sentence-map pages should not all share one shell just because they share a template name. `PAGE_STRUCTURE_VARIANT_LIBRARY_WEAK` means the book may still be usable, but it is not yet a strong reusable system.
For repeated `writing-planner` and `final-check` pages, a variant name is not enough. The renderer must emit both `data-surface-family` and `data-surface` on the actual printed surface, and the contact sheet must show a visible structure change. Missing family markers, numbered siblings, or different titles on the same grid are `metadata-only-variant` and cannot clear `PAGE_STRUCTURE_VARIANT_LIBRARY_WEAK`.

**🔴 CHECKPOINT · Workbook Record Lock**
Before scoring activity/workbook pages, inspect whether the practice area is a cohesive `workbook-record` surface. It needs a record header, numbered rows, concise prompts, and stable writing lines. Numbered practice rows should use quiet printed side numerals such as `1.` / `2.`, not zero-padded `01` component markers, square chips, option badges, or UI-control boxes. Prompt/question labels should sit above a full-width answer rule; do not use side-by-side label/rule layouts that make the line length depend on the prompt text. A loose tail of normal questions, isolated blank lines, boxed UI numbers, or shortened form-like answer rules is `loose-workbook-tail` / `workbook-practice-ui-drift`; machine QA should report `WORKBOOK_RECORD_SURFACE_MISSING` or a project-specific practice visual gate when the structure is absent.

**🔴 CHECKPOINT · Rendered Text Fidelity Lock**
Before visual release, inspect rendered PNG text for glyph ambiguity, bad punctuation spacing, and mixed CJK/Latin/digit glitches. If `11-14` looks like `1]-14`, if an apostrophe splits as `Today’ s`, or if a cover/title line looks correct in extracted text but wrong in PNG, apply `rendered-text-glitch` and repair wording, font, or spacing before scoring.

**🔴 CHECKPOINT · Starter Residue Lock**
After scaffolding a custom project and before first delivery, scan active source and generated output for starter identity: `Pathways to Better Writing`, `English Writing System`, `Sentences, Paragraphs, and Writing Practice`, `A Good Place to Observe`, `The Best Place to Think`, and `canyon-cover`. `STARTER_RESIDUE_FOUND` is P1 unless the user explicitly asked for the original starter sample.

**🔴 CHECKPOINT · User Rejection Override**
If Eric says the PDF is not good enough after a machine pass, revoke the visual pass, mark the review failed or superseded, repair the pages, regenerate screenshots, and rerun the gates. If the page set has correct components but still feels like a diagnostic form/tool rather than a printed student book, label it `diagnostic-form-drift` and rebuild the page role instead of only tuning CSS.

**🔴 CHECKPOINT · Design Transfer Reset**
If a rebuild has accumulated dashboard panels, UI number blocks, thin cover type, or component collage, stop local CSS patching. Create or use a clean design-transfer workspace, read `visual-canon.md`, `failure-taxonomy.md`, and the relevant transfer brief, then rebuild a small proof set before scaling.

## Anti-Patterns

- Do not put reference-book PDFs or screenshots into the skill.
- Do not make whole pages into images when text, exercises, answers, or tables should be editable and searchable.
- Do not imitate a raster reference PDF by exporting text-heavy pages as full-page images; reference-book raster structure is evidence to avoid, not a production route.
- Do not turn Chinese exam grammar courses into one long numbered worksheet. Map route, model, drill, mixed practice, reading transfer, writing correction, and handbook content into distinct student-book page roles.
- Do not convert 20+ lesson structured courses by skinning the existing DOCX/PDF. Read `lesson_plan.json`, question banks, passage banks, and writing banks as source data; then regenerate deterministic pages with student/teacher profile filtering.
- Do not let generated images contain teaching instructions, answer keys, fake textbook text, or watermarks.
- Do not call a proof-placeholder asset set final. In `final-assets` mode, procedural rasters, starter/sample/proof images, and ImageGen assets without prompt/source/focus/no-text manifest evidence are P1 blockers.
- Do not use a generic cover image just because it is pretty. Final cover/hero ImageGen prompts must be content-aware, with `content_brief`, `visual_direction`, and `uniqueness_note` in the manifest so each course/book can develop its own visual idea.
- Do not use hard-to-understand abstract generated imagery for final textbook visuals: paper sculptures, symbolic boards, token maps, floating strips, or concept-art contraptions are `abstract-asset-drift` unless Eric explicitly asked for that direction. Default first to realistic nature, landscape, wildlife, or animal scenes when suitable; use campus/classroom/study or modern human learning/life scenes as the second family.
- Do not reuse one image across cover, unit opener, photo passage, or inner context pages. A cover image is cover-only; `ASSET_REUSED_ACROSS_PAGES`, `COVER_ASSET_REUSED_INSIDE_BOOK`, `ASSET_PATH_REUSED_IN_MANIFEST`, and `ASSET_ALLOWED_TEMPLATE_MISMATCH` are release blockers.
- Do not place `高二升高三`, `Level 1`, or similar stage metadata as a cover-top/right badge. Keep `Eric Teaching Studio` as the cover's bottom-right brand mark.
- Do not deliver from compile success alone; full-page render review is mandatory.
- Do not self-certify visual quality by writing `FINAL_VISUAL_REVIEW: PASS` in the same run without a diagnosis, checked-page list, and reviewer provenance.
- Do not hide a failed formal review behind `PENDING`; use `FINAL_VISUAL_REVIEW: FAIL` when the proof was actually inspected and found below 9.5.
- Do not accept a contact sheet where most pages are sparse same-template cards; that is a P1/P2 redesign signal, not a pass.
- Do not call a no-student-name PDF final just because the student name was removed. A generic final book needs a new book identity and front-matter system; otherwise `GENERIC_BOOK_IDENTITY_WEAK` blocks release.
- Do not let v2 full coverage become a checklist of page-role names. If the contact sheet has long form-only stretches, treat `PAGE_ROLE_RHYTHM_WEAK` as a redesign queue rather than a harmless statistic.
- Do not let all planner/final-check pages in a long book remain one generic surface. Monthly planning, daily scheduling, answer sheets, speaking notes, listening replay, and reading evidence review are different page roles and need semantic variants plus distinct row language.
- Do not let repeated activity, skill-method, categorizing-chart, exam-mini-set, handbook, vocab-bank, article/evidence, or sentence-map pages rely on a single silent structure. Declare variants and keep an optional structure library available even when the current book only uses part of it.
- Do not let every unit opener reuse one accent color and one objectives-band structure. Keep the book unified, but rotate per-unit accent/layout metadata so each unit start has its own identity.
- Do not keep patching a failed design that has drifted into dashboard panels, UI number blocks, nested app cards, or thin cover typography; restart from the visual canon.
- Do not create a local validator that skips the skill gates because the project has custom pages, filenames, or templates.
- Do not expose QA tool names, unfinished markers, local paths, teacher-only strategy, MBTI labels, or internal workflow labels in student-facing files.
- Do not leave `answer-key` or `teacher-answer-key` pages in a clean student profile. Set `answer_visibility: student` for student PDFs, `student-with-answer-key` only for intentional student answer-key editions, and `teacher` for teacher-only outputs.
- Do not let a mixed Chinese/English cover title wrap by accident; reduce size, widen the lockup, or choose an intentional line break.
- Do not shrink one phrase of the same title-page H1, such as `for Sample Learner`, to make it feel like a subtitle. Same title means same optical scale; real subtitles belong outside the H1.
- Do not style controls with broad selectors such as `label span` or `.row span` inside text-bearing components; they will eventually style blanks, captions, title fragments, or icons by accident.
- Do not let exercise fill-in blanks float near the middle of the text line; they should read as lower-edge writing spaces, not centered underlines. The previous global `-0.64em/-0.68em` baseline is considered too high. For `Model Note` / paragraph-practice body text, use the separate `.paragraph-practice p .blank { vertical-align: -0.22em; }` cloze adjustment so short blanks do not dangle below the line. For workbook-record prompt text, use `.record-prompt .blank { vertical-align: -0.32em; }` so prompt cloze blanks do not drop like answer lines.
- Do not let word-box phrase blanks or handbook mini-rule blanks behave like full writing lines. In narrow components, keep the phrase together with `.cloze-keep`, use compact slot blanks, and move the whole phrase to the next row instead of splitting around the underline.
- Do not let activity/workbook pages end as a loose tail of questions or isolated writing lines; use `workbook-record` / `workbook-practice` with numbered rows and bounded writing space.
- Do not render practice row numbers as boxed `01` chips or UI badges; use quiet printed side numerals and keep answer lines full-width below their labels.
- Do not let a weekly planner remain a plain spreadsheet table; use a paper surface, rule strip, softer prompts, row labels, and stable writing lines.
- Do not let handbook/back-matter pages become sparse worksheets; use pale reference fields, compact lookup rows, mini rules, and table rhythm.
- Do not trust extracted text alone for final visual QA; rendered PNG glyphs and punctuation must also read cleanly.
- Do not ship student-visible text that sounds like internal workflow: `Route`, `主动作`, `维修`, `路由`, `后台`, `闭环`, `动作链`.
- Do not leave starter identity inside a custom project: `Pathways to Better Writing`, `English Writing System`, sample canyon assets, or starter paragraph titles.
- Do not treat Sample Learner or any other test student as the default book identity. Generic course books and prep plans should be no-student-name editions unless Eric explicitly asks for a personalized edition.
- Do not overwrite existing project directories, PDFs, rendered pages, or QA reports without explicit approval.

| Custom project still contains starter sample strings or assets | Replace book metadata, active page list, pages, renderer labels, Typst labels, manifest, and output names; rerun `qa_textbook_pdf.py` until `STARTER_RESIDUE_FOUND` is gone | Only set `qa.allow_starter_residue: true` when intentionally building the original starter sample |
| A generic book still contains a student/test name in title, copy, manifest prose, asset ids, output filenames, generated HTML, extracted PDF text, or visible rendered pages | Apply `student-name-residue`; remove the name in generator/source first, regenerate pages/manifest, rebuild both profiles, and rescan all layers | Use a personalized edition only when Eric explicitly asks for it; keep the personalized name out of reusable templates |
| A generic final book feels less premium after removing a student name | Apply `generic-book-identity-weak`; create a real cover/title identity in `book.yaml` (`identity.cover_title`, `identity.positioning`, `identity.audience`, `identity.front_matter_role`) and rebuild p1-p3 as publication front matter | If the cover/title still reads as a bare plan/workbook label, restart from `visual-canon.md`; do not patch only font size |
