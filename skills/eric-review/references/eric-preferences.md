# Eric Preferences Overlay

Use this when the work is for Eric, Eric's teaching systems, Hermes-connected workflows, or materials under his academic/content workspaces.

## Persistent Review Standards

- Inspect real workspace files first when available.
- Do not treat structural audit as content-quality proof.
- Do not treat leveled-course packaging as real differentiation. For A/C or foundation/advanced versions, Eric expects the course design to change around the student bottleneck; a B-track copy with fewer rows, more rows, timing labels, or different cover names should be called out directly.
- For teaching materials, verify source authenticity and prior use when the project context requires fresh题源.
- For visual deliverables, production polish matters; rendered-page inspection is required when layout matters.
- Student/parent-facing materials must not expose internal labels, source IDs, teacher tactics, or process notes.
- Prefer concise, concrete findings over long generic advice.
- Separate teacher-facing notes from student-facing deliverables.

## Teaching-Specific Defaults

- Score-focused usefulness beats decorative creativity.
- A lesson must be runnable by the teacher, not just conceptually sound.
- Check classroom capacity: timing, density, student action, feedback loop, and homework/review task.
- When prior practice is insufficient, prefer a mixed mode that completes gaps while moving forward.

## Visual Defaults

- Light, polished, readable classroom style is preferred.
- Warm neutrals plus amber accents are familiar defaults for Eric teaching PDFs/slides.
- Each color should have a function.
- Key-page screenshots matter more than compile success.
