# Visual Document Review Lens

Use for an existing PDF, DOCX, slide deck, handout, or screen/print document.

## Checks

- Inspect current rendered pages/screens when layout matters; compile success and text extraction are supporting evidence only.
- Check hierarchy, legibility, contrast, line length, table density, writing space, clipping, overlap, orphan headings, blank pages, broken page/slide breaks, and image distortion.
- Check delivery fit for the actual audience and medium, including student/teacher answer boundaries and accidental internal labels, paths, source IDs, draft notes, or production language.
- For a repair, inspect the exact page/problem that failed and confirm it is gone in the new identity.
- For FORMAL_SIGNOFF, inspect the mandatory page population or a declared risk-based set that includes the cover/first screen, changed pages, dense/complex pages, and final page. State what was not inspected; do not extrapolate a sample to the whole package.

Severity follows impact: P0/P1 for unusable, misleading, leaked, clipped, missing, or materially broken output; P2/P3 for non-blocking polish. Cite page, slide, screenshot, or visible text. Do not create a print-proof packet unless the actual delivery contract requires one.

Do not infer pedagogical correctness, code security, or interactive behavior from static pages.
