# Eric Strategic Advisory PDF

## Core outcome

Create a concise board memorandum that moves from a decision thesis to organisational consequence, operating method, engagement plan, and responsibility boundary. Keep all text searchable and use imagery only as a structural evidence field.

## Lock before building

1. Name the executive decision, audience, six-page output identity, authoritative copy, and new derivative path.
2. Preserve accepted content and page-role order when adapting an existing route. Do not restart visual research unless the route identity is rejected.
3. Refuse to overwrite source PDFs, reuse an image across pages, upload private files, use paid assets, rasterize text-heavy pages, or install the Skill globally without explicit authority.

## Six-page sequence

Use these distinct roles unless the source contract explicitly changes them:

1. Cover: decision threshold, title, one-sentence thesis, and restrained consequence cue.
2. Belief: one proposition, one explanation, audience line, and intended outcomes.
3. Audience: stepped stakeholder sequence with shared results.
4. Method: the densest page; show a complete, locally labelled operating model.
5. Engagement: phased collaboration path beside concrete deliverables.
6. Responsibility: working boundaries, human accountability, and a quiet closing line.

Avoid card walls, dashboards, repeated hero layouts, decorative icons, and generic stock-office imagery.

## Visual and colour grammar

Read [visual-production-grammar.md](references/visual-production-grammar.md) before creating or adapting source. Use one primary, one secondary, one signal colour, plus cool-grey neutrals. Keep typography and structural rules professionally dark. Reinforce every coloured distinction with labels, numbering, position, or rule weight.

Use one unique architectural, spatial, or abstract material image for each image-bearing page. Keep generated images free of text, letters, numbers, logos, and watermarks. Record source/generation, prompt or deterministic transform, page role, dimensions, text policy, hash, and unique use.

## Production workflow

1. Build deterministic A4 HTML/CSS with page-specific skeletons and selectable text.
2. Run a browser audit for six pages, loaded images, zero overflow, overlap, clipping, masking, console errors, page errors, and external URLs.
3. Export a new candidate PDF, normalize metadata into a new final derivative, and never overwrite an existing PDF.
4. Verify six A4 pages, qpdf structure, searchable extracted text, embedded fonts, no JavaScript, no blank pages, and adequate raster resolution.
5. Render all six pages from the final PDF and build a contact sheet after the final PDF/source.
6. Inspect the cover, every image-bearing page, the densest page, the method/data page, and the final page at full size.
7. Validate the Skill metadata, freeze exact PDF/contact-sheet/page-render/Skill hashes, and close the writer window.
8. Leave final approval pending for a fresh independent review of the exact frozen identity.

## Completion evidence

Return the derivative paths, exact hashes, build and QA results, colour rationale, inspected pages, and unresolved risks. Do not claim FINAL from a same-writer inspection.
