# License and originality contract

## Source classes

| Class | Adoption rule |
| --- | --- |
| User-owned | May be reused within the user's stated scope; still record the path and ownership claim. |
| MIT / ISC / Apache-2.0 | Code/assets may be adapted subject to the license and required notices. |
| CC BY | Adapt only after recording author, URL, license, and attribution placement. |
| Custom/commercial | Follow the exact terms; do not assume a free preview permits reuse. |
| Unknown | Discovery only. Adopt no code, image, icon, font, copy, or distinctive composition. |

Check nested asset licenses separately. A template license does not automatically cover its fonts, photos, illustrations, or embedded icon packs.

## Protected-expression exclusions

Exclude from the final artifact unless the user owns or separately licenses it:

- logos, names, slogans, and source copy
- original photography, illustrations, characters, mascots, and product imagery
- named artist/studio identity or “in the style of” language
- distinctive full-page composition and one-to-one component arrangement
- proprietary fonts and premium component blocks

## Transformation ledger

Record concrete changes to at least five of:

- information architecture
- page composition and proportions
- typography and type scale
- palette and contrast roles
- geometry and line system
- imagery and crop behavior
- iconography
- component grouping
- data-visualization grammar
- interaction/motion translation

Changing only colors or text is insufficient. Mixing several sources does not by itself establish originality.

## Notice policy

Keep a project-local `THIRD_PARTY_NOTICES.md` for vendored code and icons. Place visible attribution in the artifact when the source license requires it; an internal ledger is not a substitute for required public attribution.
