# Resolve consequential uncertainty

Use this method only for a consequential uncertainty. The task and host policy controls authorization and workflow; this reference adds no contract-approval or proof-approval state machine.

Inspect the narrowest available evidence first. If the requested result and authority are clear, build directly. Resolve reversible details yourself. When an assumption could invalidate costly work, make the smallest authorized representative proof and show what it establishes.

Ask only about a material unresolved choice involving the product result, cost, scope, external effect, or irreversibility. A user's explicit delegation resolves the delegated choice; an explicit instruction to continue authorizes continuation within its existing scope. Do not request a second ceremonial confirmation of the same decision.

If the user explicitly withheld editing or required sample approval before scaling, preserve that boundary. Positive feedback alone is not permission to exceed an explicit restriction. If the proof changes the intended product, resolve the changed requirement before expanding affected work; do not reopen unrelated settled choices.

Record the decisive assumption in ordinary task communication. Persist a contract only when requested or required for a real handoff. Identity hashes belong at immutable release or reproducibility boundaries, not every reversible sketch.
