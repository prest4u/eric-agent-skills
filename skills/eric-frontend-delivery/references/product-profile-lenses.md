# Product-profile lenses

Use one primary lens only when it improves the requested product surface. Lenses refine product fidelity; they never override the acceptance criterion, project design system, authoritative brief, or accessibility basics.

## Workflow and forms

Prioritize task sequence, field grouping, labels, validation timing, error recovery, progress, saved-state feedback, destructive confirmation, and focus movement. Keep the next action obvious without hiding advanced controls users need.

## Dashboard and data

Prioritize decision hierarchy, time/context labels, comparison baselines, units, empty/loading/error states, table/chart accessibility, density, filtering feedback, and small-screen transformation. Never fabricate metrics or replace a working task surface with decorative charts.

## Content and marketing

Prioritize audience promise, reading order, scan rhythm, credible proof, action clarity, media provenance, text reflow, and restrained motion. This lens applies only when the requested product really is content-led; do not wrap an application in an invented landing page.

## Interactive UI

Prioritize discoverability, direct manipulation, state persistence, feedback latency, keyboard equivalence, focus return, reduced-motion behavior where applicable, and clear recovery. Verify transitions through the real runtime rather than inferring them from source.

## Cross-lens rule

If the surface spans lenses, select the lens governing the primary user outcome and use only the relevant checks from another. Record a product-fidelity gap when visual polish competes with task completion, familiar controls, or project-native conventions.
